# SecureChat

A zero-dependency, end-to-end encrypted chat app built with a **Java relay server** and a **single-file HTML client**. Messages are encrypted in the browser with AES-256-GCM, so the server only ever sees ciphertext.

> End-semester Java project, B.Tech CSE, SRM AP.

---

## Features

| Feature | What it does |
|---|---|
| **End-to-end encryption** | AES-256-GCM in the browser (Web Crypto API). The key is derived from a shared room key using PBKDF2 (SHA-256, 150,000 iterations). The server never sees the key or the plaintext. |
| **Encryption indicator** | A status pill shows whether the session is encrypted. |
| **Self-destruct messages** | Set a timer (up to 300 seconds) and the message is deleted from the server and every client when it expires. |
| **Burn after read** | When someone other than the sender reads the message, an 8-second countdown starts and the message is then destroyed. |
| **Smart replies** | Quick-reply suggestions generated by on-device, rule-based logic. Nothing leaves the browser. |
| **Offline message queue** | Messages sent while offline are stored locally and sent automatically on reconnect. Each message has a client ID (`cid`), so resends never create duplicates. |
| **Emoji reactions** | React to any message with one of six emojis (smile, laugh, heart eyes, thumbs up, sad, angry). Click again to remove. |
| **Room mood meter** | A live mood bar built from message sentiment and reactions over the last 10 messages. |
| **File sharing with preview** | Share PNG, JPG, GIF, WEBP (up to 2 MB) and PDF (up to 3 MB) with inline preview. Files are encrypted like messages. |
| **Live presence** | See who is currently online in the room. |
| **Transcript export** | Export the chat as an HTML transcript (self-destructed messages are excluded). |

## How it works

```
 Browser A                        Java Server                      Browser B
 ---------                        -----------                      ---------
 room key -> PBKDF2 -> AES key
 plaintext -> AES-256-GCM -> ciphertext --> relay + store --> ciphertext -> AES-256-GCM -> plaintext
                                   |
                         only ciphertext is
                         visible / logged here
```

- **Transport:** the client opens one long-lived **Server-Sent Events (SSE)** connection (`/events`) for realtime delivery and sends actions with plain HTTP `POST` requests.
- **Zero-knowledge server:** the server stores and forwards opaque ciphertext. It handles timers, reactions, presence and duplicate protection without ever decrypting anything.
- **Proof:** `server_log.txt` records message metadata and the first characters of each ciphertext, showing the server cannot read the content.

### API endpoints

| Endpoint | Method | Purpose |
|---|---|---|
| `/` | GET | Serves `index.html` |
| `/events?user=<name>` | GET (SSE) | Realtime stream: messages, reactions, presence, deletions |
| `/send` | POST | Submit an encrypted message (`user`, `cid`, `cipher`, `mode`, `ttl`) |
| `/react` | POST | Toggle an emoji reaction on a message |
| `/read` | POST | Mark a burn-after-read message as read |

## Getting started

### Requirements
- **Java 17 or newer** (uses records and the built-in `com.sun.net.httpserver`)
- A modern browser (Chrome, Edge, Firefox, Safari)

### Run

```bash
# 1. Compile
javac ChatServer.java

# 2. Start the server
java ChatServer
```

Open **http://localhost:8080** in two browser tabs.

### Use

1. Enter a **display name**.
2. Enter a **room key**. Everyone in the same room must use the **same key**.
3. Click **Join room** and start chatting.

Anyone who joins with a different room key will see *"Cannot decrypt: sent with a different room key"*.

> **Secure context required.** Browsers only enable the Web Crypto API on `localhost` or HTTPS. If you open the app over a plain `http://<ip-address>`, encryption is unavailable. To chat across devices, serve the app over HTTPS (for example through a reverse proxy or a tunnel).

## Tech stack

- **Backend:** Java 17, `com.sun.net.httpserver`, Server-Sent Events, `java.util.concurrent`
- **Frontend:** HTML, CSS, vanilla JavaScript
- **Crypto:** Web Crypto API (AES-256-GCM, PBKDF2-SHA-256)
- **Dependencies:** none

---

## Limitations

This is an academic project, not a production messenger.

- Chat history is kept **in memory** and is lost when the server restarts.
- There is **no user authentication**. Anyone with the room key can join under any name.
- The PBKDF2 salt is a fixed value, so use a long, strong room key.
- Reactions, timers and read receipts are visible to the server (metadata is not encrypted).
- Attachment sizes are limited (2 MB images, 3 MB PDFs).
